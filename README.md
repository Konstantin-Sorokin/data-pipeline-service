# Data Pipeline Service

Сервис для синхронизации файлов с внешним провайдером данных, подсчёта статистики по цифрам в содержимом файлов и отображения результатов через веб-интерфейс.

---

## Возможности

- Синхронизация файлов с внешним API провайдера
- Распаковка ZIP-архивов и сохранение файлов на диск
- Подсчёт количества вхождений каждой цифры (0–9) в содержимом файлов
- Просмотр списка скачанных файлов с пагинацией и статистикой
- Расчёт суммарной статистики по выбранным или по всем файлам
- Кеширование результатов статистики в Redis
- Отслеживание статуса синхронизации в реальном времени (через Redis + polling на фронтенде)
- Автоматическое применение миграций БД при запуске

## Архитектура

### Обработка HTTP-запросов

```
Browser
    ↓
Nginx (прокси, порт 85 или любой установленный в docker compose)
    ↓
FastAPI (app)
    ↓
PostgreSQL
```

Nginx раздаёт статические файлы напрямую, а запросы к API проксирует на FastAPI-приложение.

### Асинхронная синхронизация файлов

```
Browser → POST /api/sync → FastAPI (ставит задачу в Celery)
                                    ↓
                            Celery Worker (sync_files_task)
                                    ↓
                            FileProviderClient (внешнее API)
                                    ↓
                            Распаковка ZIP → Сохранение на диск
                                    ↓
                            Подсчёт статистики → Запись в БД
                                    ↓
                            Обновление статуса в Redis
```

## Запуск проекта

1. Клонировать репозиторий:

```bash
git clone https://github.com/Konstantin-Sorokin/data-pipeline-service.git
cd data-pipeline-service
```

2. Создать файл `.env` на основе шаблона:

```bash
cp .env.template .env
```

Заполнить обязательные переменные (см. раздел «Переменные окружения»).

3. Запустить сервисы:

```bash
docker compose up --build
```

Миграции базы данных применяются автоматически при запуске контейнера `app` (через `scripts/start-api.sh`).

## API

Все эндпоинты, кроме страниц, находятся за префиксом `/api`.

### Синхронизация

`POST /api/sync` — запустить синхронизацию файлов с внешним провайдером (через Celery).

`GET /api/sync` — получить текущий статус синхронизации (из Redis).

### Файлы

`GET /api/files?page=1&page_size=50` — получить список скачанных файлов с пагинацией и статистикой по цифрам.

### Статистика

`POST /api/statistics` — получить суммарную статистику по цифрам.

Тело запроса:

```json
{
  "file_ids": [1, 2, 3],
  "all_files": false
}
```

Параметр `all_files: true` возвращает статистику по всем файлам (с кешированием в Redis).

### Страницы

`GET /files` — страница со списком файлов и управлением расчётами.

`GET /download` — страница загрузки с информацией о статусе синхронизации.

---

## Асинхронные задачи

Celery используется для выполнения синхронизации файлов в фоновом режиме.

**`sync_files_task`** — загружает список имён файлов от внешнего провайдера, скачивает ZIP-архивы, распаковывает их, сохраняет файлы на диск, подсчитывает статистику по цифрам и записывает данные в БД. В процессе выполнения обновляет статус в Redis (queued → running → completed / failed).

При получении ошибок `429 Too Many Requests` или `403 Blocked` задача автоматически повторяется с учётом заголовка `Retry-After`.

## Интерфейс

Приложение имеет две страницы, доступные через браузер:

- **Файлы** (`/files`) — таблица скачанных файлов с пагинацией, возможностью выбора файлов, расчёта суммарной статистики по выбранным файлам и просмотра общей статистики по всем файлам.
- **Загрузка** (`/download`) — страница для запуска синхронизации с внешним провайдером и отслеживания её статуса в реальном времени.

Навигация между страницами осуществляется через навигационную панель.

## Особенности реализации

- **Unit of Work** — паттерн для управления транзакциями: при успешном выполнении контекстного менеджера изменения коммитятся, при ошибке — откатываются.
- **Repository** — абстракция доступа к данным (FileRepository, CalculationRepository).
- **Redis-кеш** — суммарная статистика по всем файлам кешируется в Redis с ключом `statistics:all`.
- **Redis-статус синхронизации** — ход выполнения синхронизации (total, downloaded, status) хранится в Redis и отслеживается на фронтенде через polling.
- **Пагинация** — API endpoint `/api/files` поддерживает постраничную выдачу с параметрами `page` и `page_size`.
- **Обработка rate limit** — клиент внешнего API соблюдает задержку между запросами (0.8 с) и обрабатывает ошибки 429 и 403 с повторными попытками.
- **Файловое хранилище** — скачанные файлы сохраняются в локальную директорию `storage/`.
- **Асинхронность** — весь I/O (HTTP-клиент, БД, Redis) реализован через async/await.
- **Pydantic-схемы** — валидация входных и выходных данных на всех API-эндпоинтах.
